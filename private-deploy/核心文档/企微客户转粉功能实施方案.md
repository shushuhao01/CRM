## 一、业务设计

### 1.1 背景

企业微信的「客户联系」体系中，客户归属企业而非员工个人。当员工**工作变动（在职继承）**或**离职/账号被封（离职继承）**时，企业可将其名下微信客户重新分配给其他成员继续服务，即"转粉"。本系统已是企微服务商（第三方应用模式，Suite 授权链路已跑通），具备代客户企业调用该能力的天然条件。

### 1.2 商品定义（两种，均收费）

| 商品 | packageId 前缀 | 计费方式 | 交付物 | 权益 |
|---|---|---|---|---|
| **转粉代办服务** | `convert_agent_` | 按次/按客户数阶梯计价（定价后台可配） | 租户提交工单 → 服务商在 Admin 操作台代执行 → 24h 自动接替 | 不解锁菜单，走工单闭环 |
| **自助转粉权限** | `convert_self_` | 按期收费（季度/年度，定价后台可配） | 解锁 CRM「客户转粉」菜单，租户自行操作 | `menuPermissions.customerConvert = true` |

### 1.3 业务边界与官方限制（必须遵守）

| 规则 | 在职继承 | 离职继承 |
|---|---|---|
| 90 天内同一客户最多转接次数 | **2 次** | **不限制**（官方原文：在职继承的次数限制不影响离职继承） |
| API 单次客户数 | ≤ 100 | ≤ 100 |
| 后台页面单次 | ≤ 5000 | ≤ 5000 |
| 接替生效时间 | 发起后 **24 小时**自动接替，客户可拒绝 | 同左 |
| 原跟进人状态 | 在职，近一年内登录过 | 已从通讯录删除，离职 ≤ 1 年且离职前一年内登录过（**主动注销的账号不可继承**） |
| 接替人要求 | 应用可见范围内 + 已配置客户联系 + 激活 + 实名，近一年内登录过 | 同左 |
| 客户群 | 每群 90 天 2 次；同一新群主每天最多接 300 个群 | 群主离职后可分配 |

> 本期实现范围：**客户（外部联系人）的在职/离职继承**。客户群继承作为二期预留（接口见 2.5）。

## 二、官方接口规范（开发依据）

> 以下全部来自企微官方文档（2023-12-01 更新版），开发时以此为准，不得自行变更字段。
> 官方链接：在职分配 `96325` / 在职结果 `94088` / 待分配离职列表 `96330` / 离职分配 `96331` / 离职结果 `96333` / 在职群分配 `95703`。

### 2.1 分配在职成员的客户（发起在职转粉）

```
POST https://qyapi.weixin.qq.com/cgi-bin/externalcontact/transfer_customer?access_token=ACCESS_TOKEN
```

请求体：
```json
{
    "handover_userid": "zhangsan",
    "takeover_userid": "lisi",
    "external_userid": [
        "woAJ2GCAAAXtWyujaWJHDDGi0mACAAAA",
        "woAJ2GCAAAXtWyujaWJHDDGi0mACBBBB"
    ],
    "transfer_success_msg": "您好，您的服务已升级，后续将由我的同事李四@腾讯接替我的工作，继续为您服务。"
}
```

| 参数 | 必须 | 说明 |
|---|---|---|
| handover_userid | 是 | 原跟进成员的 userid |
| takeover_userid | 是 | 接替成员的 userid |
| external_userid | 是 | 客户的 external_userid 列表，**每次最多 100 个** |
| transfer_success_msg | 否 | 转移成功后发给客户的消息，最多 200 字符，不填用默认文案 |

响应（**逐客户结果**，errcode=0 仅代表成功发起、待 24h 自动接替）：
```json
{
    "errcode": 0,
    "errmsg": "ok",
    "customer": [
        { "external_userid": "woAJ2GC...AAAA", "errcode": 40096 },
        { "external_userid": "woAJ2GC...BBBB", "errcode": 0 }
    ]
}
```

权限说明（官方原文）：
- **第三方应用需拥有「企业客户权限→客户联系→在职继承」权限**
- 接替成员必须在此第三方应用的**可见范围内**
- 接替成员需要配置了客户联系功能、企微激活且已实名认证
- 原跟进成员和接替成员在最近一年内需登录过至少一次企业微信

### 2.2 查询客户接替状态（在职）

```
POST https://qyapi.weixin.qq.com/cgi-bin/externalcontact/transfer_result?access_token=ACCESS_TOKEN
```

请求体：
```json
{ "handover_userid": "zhangsan", "takeover_userid": "lisi", "cursor": "CURSOR" }
```

响应：
```json
{
    "errcode": 0,
    "errmsg": "ok",
    "customer": [
        { "external_userid": "woAJ2GC...CCCC", "status": 1, "takeover_time": 1588262400 },
        { "external_userid": "woAJ2GC...BBBB", "status": 2, "takeover_time": 1588482400 },
        { "external_userid": "woAJ2GC...AAAA", "status": 3, "takeover_time": 0 }
    ],
    "next_cursor": "NEXT_CURSOR"
}
```

| status | 含义 |
|---|---|
| 1 | 接替完毕 |
| 2 | 等待接替（takeover_time 为未来的自动接替时间） |
| 3 | 客户拒绝 |
| 4 | 接替成员客户达到上限 |

### 2.3 获取待分配的离职成员列表

```
POST https://qyapi.weixin.qq.com/cgi-bin/externalcontact/get_unassigned_list?access_token=ACCESS_TOKEN
```

请求体：
```json
{ "cursor": "", "page_size": 100 }
```

| 参数 | 说明 |
|---|---|
| page_size | 默认 1000，**最大 1000** |
| cursor | 分页游标，由上一次调用返回 |

响应：
```json
{
    "errcode": 0,
    "errmsg": "ok",
    "info": [
        {
            "handover_userid": "zhangsan",
            "external_userid": "woAJ2GC...AAAA",
            "dimission_time": 1550838571
        }
    ],
    "is_last": false,
    "next_cursor": "aSfwejksvhToiMMfFeIGZZ"
}
```

权限：**第三方应用需拥有「企业客户权限→客户联系→分配离职成员的客户」权限**。

### 2.4 分配离职成员的客户（发起离职转粉）

```
POST https://qyapi.weixin.qq.com/cgi-bin/externalcontact/resigned/transfer_customer?access_token=ACCESS_TOKEN
```

请求体（同 2.1，但**无** transfer_success_msg 字段）：
```json
{
    "handover_userid": "zhangsan",
    "takeover_userid": "lisi",
    "external_userid": ["woAJ2GC...BBBB", "woAJ2GC...AAAA"]
}
```

限制（官方原文）：
- handover_userid 必须是**已离职用户**；离职时间不超过 1 年且离职前一年内至少登录过一次
- 接替成员最近一年内至少登录过一次
- **每次最多 100 个客户**
- 响应中 errcode=0 同样仅代表开始分配流程，待 24h 后自动接替

### 2.5 查询离职接替状态 / 在职客户群分配（二期预留）

- 离职接替结果：`POST /cgi-bin/externalcontact/resigned/transfer_result`，请求/响应结构同 2.2
- 在职客户群分配：`POST /cgi-bin/externalcontact/groupchat/onjob_transfer`，`{ "chat_id_list": [1~100个], "new_owner": "zhangsan" }`，返回 `failed_chat_list`
- 离职客户群分配：`POST /cgi-bin/externalcontact/groupchat/resigned/transfer_result` 等，见官方文档 96333/95703 系列

## 四、总体架构设计

```
┌─ CRM 主应用（租户端）──────────────────────┐   ┌─ Admin 管理后台（服务商端）────────────────┐
│ 企微管理 → 客户转粉 (CustomerConvert.vue)   │   │ 企微管理 → 转粉服务台 (TransferFan.vue)     │
│  · 未购买：服务介绍 + 代办下单 + 自助购买    │   │  · 代办工单处理（审核/执行/拒绝）            │
│  · 已购买：自助在职/离职转接 + 记录          │   │  · 任意租户代执行转粉（在职/离职/选人选客户）│
└──────────────┬─────────────────────────────┘   │  · 全局转接记录与成功率统计                  │
               │ /api/v1/wecom/convert-fan/*     └──────────────┬──────────────────────────────┘
               │                                                │ /api/v1/admin/wecom-management/convert-fan/*
               └───────────────────┬────────────────────────────┘
                                   ▼
                    backend/src/routes/wecom/convertFan.ts（租户端）
                    backend/src/routes/admin/wecom-management.ts（扩展转粉段）
                                   ▼
                    services/WecomConvertFanService.ts（核心业务编排）
                    services/WecomApiService.ts（新增 5 个官方 API 方法）
                    services/wecom/WecomTokenService.getAccessTokenByConfigId(configId,'corp')
                                   ▼
                    企微官方 API（transfer_customer / transfer_result / get_unassigned_list / resigned/*）
                                   ▼
                    SchedulerService 定时任务 wecom-transfer-result-sync（每 15 分钟轮询接替结果）
```

**核心流程时序（代办模式）**：

```
租户CRM: 提交代办工单 → createOrder(convert_agent_xxx) → 展示支付二维码
支付回调: payment_orders → paid → syncCrmVasBilling → 工单状态 pending→paid(待处理)
Admin:   服务商看到工单 → 审核 → 代执行（分批调 transfer_customer，落库逐客户结果）
定时任务: 24h 后轮询 transfer_result → 更新 status(success/partial/rejected)
租户CRM: 实时查看工单进度与最终结果
```

**核心流程时序（自助模式）**：

```
租户CRM: 购买自助权限(convert_self_quarterly) → 支付 → unlockTenantPermissions('convert')
         → menuPermissions.customerConvert=true → 前端菜单解锁
租户CRM: 选转接类型(在职/离职) → 离职先调 get_unassigned_list 拉池子 → 选接替人 → 勾选客户
         → POST /convert-fan/execute → 后端校验权限+分批调官方API → 返回逐客户结果
定时任务: 轮询 transfer_result 更新状态
```

```typescript
{

    resultDetail:  text/JSON     // 轮询回填 [{external_userid, status, takeover_time}]
```

### 6.3 WecomApiService 新增方法（完全按官方文档）

```typescript
// ===== 客户转粉（在职/离职继承）=====
// 发起在职转接。externalUserids ≤100，msg ≤200字符
```

### 6.4 WecomConvertFanService（核心编排）

```typescript
class WecomConvertFanService {
    // 拉取离职待分配池（聚合全部分页）
    async listUnassignedCustomers(tenantId: string)

    // 发起转粉（代办与自助共用核心）
    // 校验顺序：租户企微配置可用 → 权限（自助必须 customerConvert=true）→
    //           transferType 合法 → externalUserids 去重切批(≤100) →
    //           在职场景前端传 transfer_success_msg(≤200字符，超长截断)
    async executeTransfer(params: {
        tenantId: string; mode: 'agent' | 'self'; transferType: 'active' | 'resigned';
        handoverUserid: string; takeoverUserid: string;
        externalUserids: string[]; transferSuccessMsg?: string;
        operatorId: number; operatorName: string
    }): Promise<{ orderNo: string; submitResult: [...] }>
    // 内部：逐批调 transferActiveCustomer / transferResignedCustomer
    //      订单初始 status='submitted'，submitResult 落库
    //      批间 sleep 500ms 防频控；全批 errcode≠0 → status='failed'

    // 定时轮询入口（SchedulerService 每15分钟调用）
    async syncTransferResults(): Promise<void>
    // 查 status IN ('submitted','partial') 且 createdAt < 24h 的订单
    // （发起后立即轮询无意义，官方 24h 才自动接替；但客户可能提前主动添加，
    //   所以 submitted 订单创建 1 小时后即可开始轮询）
    // 逐单调 getActive/ResignedTransferResult → 聚合：
    //   全部 status=1 → success；存在 1 且存在 3/4 → partial；全部 3 → rejected
    //   存在 3/4 且无 1 → 保持 submitted（24h 内客户仍可能添加）；
    //   createdAt 超过 7 天仍有非终态 → 按当前快照落终态并标记 lastSyncAt
    // successCount 回填；终态订单写租户站内消息（message 模块现有能力）

    // 支付成功联动（PaymentService 回调 convert_ 前缀时调用）
    async onPaid(orderNo: string, packageId: string): Promise<void>
    // convert_agent_* → 对应工单 status: pending → paid（进入待处理队列）
    // convert_self_*  → 写权益台账 + unlockTenantPermissions(tenantId, 'convert')
}
export const wecomConvertFanService = new WecomConvertFanService()
```

**权限校验细则（executeTransfer 内）**：
- `mode === 'self'`：读 `tenant_wecom_package_{tenantId}` 的 `menuPermissions.customerConvert !== true` 则 403（文案：请先购买自助转粉权限）；同时校验权益台账 `endDate > now`，过期则 403 提示续费
- `mode === 'agent'`：必须来自 admin 路由调用（adminAuth 中间件保证），且工单 `payOrderNo` 对应支付单已 paid
- 每位客户 90 天 2 次（在职）由官方侧拦截，返回子 errcode 时透出即可，系统不做预校验（避免口径不一致）

|---|---|---|
| 0 | 成功发起（非最终成功） | status='submitted'，等待轮询 |
| 40096 | external_userid 不属于原跟进人 | 该客户标记失败，提示核对归属 |
| 81001 | 无权限/接替人不在可见范围 | 整批中止，提示检查应用可见范围 |
| 60011 | 无权限调用接口（官方权限未申请/未重新授权） | 提示"企微权限未开通，请检查服务商后台权限或让租户重新授权" |
| 84019 | 缺少 external_userid 参数 | 前端拦截（不允许空提交） |
| 40058 | 参数错误 | 记录原始报文，报警日志 |
| 45009 | 接口频率超限 | 批间 sleep 已做 500ms；触发时退避 2s 重试一次 |
| 40001 | access_token 失效 | 清 token 缓存重试一次（WecomTokenService 已有机制） |
| 84060 | 不存在外部联系人的关系（离职场景已接替完） | 该客户标记跳过 |

## 十二、测试计划

### 12.1 单元/接口测试（backend jest）

- WecomApiService 5 个新方法：mock axios 断言 URL/body/分页聚合/errcode 抛错
- executeTransfer：分批切片（101→2 批）、权限 403、工单状态机流转
- onPaid：agent/self 两种 packageId 分流、续费 endDate 叠加
- syncTransferResults：四态聚合逻辑（全 1→success；混合→partial；全 3→rejected；超 7 天兜底）

### 12.2 联调测试（需真实企微环境）

> 准备：1 个测试企业（已授权 Suite，含 ≥3 成员 A/B/C，A 加 ≥2 个微信客户），服务商后台开通继承权限。

| 用例 | 步骤 | 预期 |
|---|---|---|
| 离职转接全流程 | 删除成员 A（离职）→ CRM 未购权访问转粉页被拦 → 购买自助权限 → 拉待分配池看到 A 的客户 → 全选转给 B → 24h（可让客户提前点添加）后轮询 | 订单 success，B 收到好友，客户微信出现 B 会话 |
| 在职转接 | A 在职，转 1 客户给 C | 24h 后接替；A 无法再服务该客户 |
| 客户拒绝 | 转接后客户点"暂不添加" | 轮询落 rejected，记录可见 status=3 |
| >100 分批 | 准备 120 客户（或 mock） | 2 批发起，submitResult 合计 120 条 |
| 90 天限制 | 同一客户第 3 次在职转接 | 子 errcode 报错透出 |
| 代办闭环 | 租户下代办单 → 支付 → admin 执行 | 工单 pending→paid→success；审计日志有记录 |
| 权限到期 | 台账 endDate 改为过去 | execute 403，菜单重新锁定 |
| 注销账号边界 | 成员主动注销后查待分配池 | 该成员客户不出现/不可操作（官方限制，验证提示） |

### 12.3 回归

购买组件三处 type 扩展不影响原 wecom/archive/ai/acquisition 购买；守卫对旧菜单无影响。
